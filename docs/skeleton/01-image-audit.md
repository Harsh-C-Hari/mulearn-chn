## 2. Existing loading architecture

* All photographic `<img>` carry `width`/`height` + CSS `aspect-ratio`, so **space is already reserved** — no layout shift risk from the images themselves.
* `loading="lazy"` on 50/52 (only hero and lightbox are eager). `decoding="async"` everywhere.
* Only existing state logic: `js/memories.js` lightbox adds `.is-loading` (opacity .55) and clears it on `load`/`error`/`complete`. The **old photo stays visible under the new caption** until the new one decodes.
* **No error fallback exists** anywhere: a failed image shows the browser's broken-image glyph / alt text.
* `<html>` gets `.js` / `.no-js` from an inline head script. `.pre-motion` hides the hero for ≤1.2 s (GSAP entrance) – the skeleton must not fight it.
* Cards (`event-card__poster`, `member-card__photo`) are **rotated** and have hard shadows; the mat is the host's padding, so an overlay must be inset by the mat to match the image box exactly.

## 3. Generated markup constraint (important)

`index.html` regions between `*:start` / `*:end` markers are generated by `scripts/build_events.js`, `build_team.js`, `build_memories.js`. **Editing the HTML there would be overwritten.** The system therefore must not require per-image HTML changes: variants are resolved by CSS selectors in JS. Only one `<link>` and one `<script>` are added outside the generated regions.

## 4. Layout-shift risks

| Risk | Where | Handling |
|------|-------|----------|
| Skeleton box ≠ image box | mats/padding on posters, portraits, About | overlay inset = host padding, same border/radius as the image |
| Lightbox old image stretched/jumps while swapping | stage | skeleton box takes the new photo's ratio from `width/height` before the bytes arrive |
| Mini thumb on <700px (`height:100%` image) | event-mini | overlay centred to image ratio inside fixed 4/3 host |
| Tilted hosts | posters/portraits | overlay is a child of the tilted host → inherits rotation |
| Hosts with `position:static` | mini thumb, dialog photo, lightbox stage | `position:relative` added in skeleton CSS only |
